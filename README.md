## 你一定经历过

**收藏了，就等于学会了。**

几百篇文章躺在收藏夹里，真正消化过的不超过十篇。当时保存时明明有想法，过三个月再看——完全不记得当初为什么觉得它重要。原网页改了、删了，你连 AI 当时读了什么都说不清。维护交叉引用、检查矛盾、更新过时内容，逐渐变成一份兼职工作，成本随笔记数量增长而急剧上升。

**或者，你已经试过让 AI 全自动接管。**

把资料喂给 AI，它帮你编译成结构化的 Wiki，自动建立链接、检测矛盾、更新内容。听起来很美——你几乎不用动手。但几个月后你发现：Wiki 里的内容你从未真正读过，AI 替你做了编辑判断，重要细节被丢弃而你毫不知情。更危险的是，Wiki 的过时看起来像“自信的错误信息”，你根本不会怀疑。你拥有了一个知识库，但它里面的知识不属于你。

---

## EngramWeave 的选择

一句话：**AI 负责编译，你负责定稿。**

把你在网页、论文和实验中看到的内容，连同当时的想法、疑问与判断一起保存。AI 阅读来源、提炼要点、发现关系、规划整合——但**它永远只能提案，不能拍板**。正式知识以普通 Markdown 存在你自己的 Obsidian 库里，可读、可迁移、可备份。

> **AI 认为** ≠ **我认可**
>
> 这是贯穿全篇的唯一设定。

## 三条路线的本质差异

| | 传统知识管理（Obsidian / Notion） | LLM Wiki 全自动路线 | EngramWeave |
|---|---|---|---|
| **知识从哪来** | 你手动写笔记、建链接、分类 | AI 全自动编译，人几乎不写 | AI 编译草稿，**你逐条确认后才成为正式知识** |
| **AI 的角色** | 基本没有 | 知识库的**唯一作者和维护者** | 理解、建议、提案——**你才是作者** |
| **你的角色** | 全部手动劳动 | 提供素材和规则，**信任 AI 的判断** | 判断什么值得留下，**决定哪些关系成立** |
| **产出是什么** | 你的笔记文件 | AI 维护的 Wiki 页面 | **你认可的知识**，存在你自己的 Markdown 里 |
| **失效模式** | 维护成本过高，最终放弃 | 幻觉污染、自信的错误、知识归属感丧失 | 需要你投入判断——但每次投入都在塑造你自己的知识体系 |
| **长期结果** | 收藏夹，越积越不想打开 | 一个你“拥有”但没读过的 Wiki | **一个你真正理解、信任、能回忆的外置认知系统** |

## 一次完整使用

```text
看到有价值的内容
      │
      ▼
采集：连同当时的想法一起保存        ← 保存的是「认知上下文」，不只是链接
      │
      ▼
来源留存：留下当时的原文快照        ← 网页会消失，证据不会
      │
      ▼
AI 编译：阅读来源 → 形成知识草稿    ← 提炼要点、事实、主张、概念、不确定处
      │
      ▼
AI 关系发现：指出与已有知识的联系    ← 支持、矛盾、替代、继承、实现、证据
      │
      ▼
══════ 人工闸门 ①  我认可哪些草稿与关系 ══════
      │
      ▼
AI 整合规划：决定如何融入已有体系    ← 优先复用已有结构，避免重复新建
      │
      ▼
变更提案：拆成可逐条决定的改动       ← 每条标明目标、改动前后、理由与来源
      │
      ▼
══════ 人工闸门 ②  我逐项批准哪些改动 ══════
      │
      ▼
正式知识（可追溯、可检索）
      │
      └──► 长期维护：只提案，不自动改动
```

## 核心能力

**📥 采集** — 几秒内把内容送进系统，同一个动作记下“为什么保存”。资料的价值一半来自内容，一半来自保存时你的判断。

**📸 来源留存** — 网页会改、会删、会失效。每条知识都能点回来源，看到原始网址、采集时间与当时快照。论据沿「知识 → 来源 → 快照 → 原网址」可完整回溯。

**🧠 知识编译** — AI 阅读来源，结合你保存时写下的想法，提炼要点、事实、主张、概念、方法与不确定之处。只产出草稿，不写入知识库。

**🔗 关系发现** — 检索已有知识，指出新内容与旧知识的具体关系（支持、矛盾、替代、继承等），带类型、理由与出处，可逐条接受、拒绝、修改或追问。

**⚖️ 人工确认闸门** — 并排呈现原始来源、你的批注、AI 草稿与关系建议。**这是「AI 认为」与「我认可」的分界点。** AI 不替用户拍板；未经审阅认可的草稿不会进入知识库。

**📐 整合规划与变更提案** — 你确认后，AI 规划新建还是更新、归入哪一类、链接到谁，再拆成一条条具体变更。每条可逐项接受、编辑、拒绝或成组接受。优先复用已有结构，改动透明、可解释、可撤销。

**📄 正式知识** — 批准后的内容以普通 Markdown 存入你的 Obsidian 库。**即使产品停止维护、AI 服务消失或索引损坏，正式知识仍完整存在。**

**🔍 检索与取回** — 支持从文件名、全文、元数据、关系等层次找回知识。即使只记得「我好像研究过这个」，也能迅速找回当时的知识、来源、想法与判断。

**🛠️ 知识维护** — 周期性检查知识库，提出整理、修复、更新与继续研究方向的建议。打开系统时自行查看，**绝不自动推送、合并或删除**。

**🔬 科研工作区** — 以研究问题为中心组织假设、论文、实验与证据。证据地图把支持与反对某结论的证据并排呈现。*（后续阶段）*

**🔌 对外接口** — 向外部 AI 助手开放知识库，让它们基于你的知识回答。默认「只读 + 提案」，写权限须单独授权。*（后续阶段）*

## 三条不可妥协的约束

**🔐 数据主权** — 正式知识以普通 Markdown 存在你自己的 Obsidian 库里，论文与引用以 Zotero 为准。系统内部只保存索引、草稿、任务与提案这类派生数据，原则上都可重建。

**🛡️ 权限** — AI 与外部工具默认只能读取与提案；所有正式知识的修改都逐项确认，并可完整回滚。

**🌱 长期演化** — 维护只建议、不推送；检索可随时回取；不做任何强制复习与提醒。随时记录，随用随取。

## 快速开始

### 环境依赖

- Node.js LTS（建议 20 或以上）
- npm（随 Node 一起安装）
- Obsidian（用于阅读与审核知识）
- Rust 工具链（仅在构建 Tauri 桌面端时需要）

### 安装

```bash
git clone https://github.com/EngramWeave/EngramWeave.git
cd EngramWeave
npm install
```

### 运行

```bash
# 启动本地 Core 服务
npm run core

# 启动桌面端（开发模式）
npm run desktop:dev
```

详细开发说明、API 契约与模块划分见 [P1 工程文档](./docs/P1-README.md)。
