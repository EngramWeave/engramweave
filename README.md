## 你一定经历过

**收藏了，就等于学会了。**

几百篇文章躺在收藏夹里，真正消化过的不超过十篇。当时保存时明明有想法，过三个月再看——完全不记得当初为什么觉得它重要。原网页改了、删了，你连当时读了什么都说不清。维护交叉引用、检查矛盾、更新过时内容，逐渐变成一份兼职工作，成本随笔记数量增长而急剧上升。

**或者，你已经试过让 AI 全自动接管。**

把资料喂给 AI，它帮你编译成结构化的 Wiki，自动建立链接、检测矛盾、更新内容。听起来很美——你几乎不用动手。但几个月后你发现：Wiki 里的内容你从未真正读过，AI 替你做了编辑判断，重要细节被丢弃而你毫不知情。更危险的是，Wiki 的过时看起来像“自信的错误信息”，你根本不会怀疑。你拥有了一个知识库，但它里面的知识不属于你。

---

## EngramWeave 的选择

一句话：**AI 负责编译，你负责定稿。**

把你在网页、论文和实验中看到的内容，连同当时的想法、疑问与判断一起保存。AI 阅读来源、提炼要点、发现关系、规划整合——但**它永远只能提案，不能拍板**。正式知识以普通 Markdown 存在你自己的 Obsidian 库里，可读、可迁移、可备份。

> **AI 认为** ≠ **我认可**
>
> 这是贯穿全篇的唯一设定。

## 三条路线的本质差异

| | 传统知识管理（Obsidian / Notion） | LLM Wiki 全自动路线 | EngramWeave |
|---|---|---|---|
| **知识从哪来** | 你手动写笔记、建链接、分类 | AI 全自动编译，人几乎不写 | AI 编译草稿，**你逐条确认后才成为正式知识** |
| **AI 的角色** | 基本没有 | 知识库的**唯一作者和维护者** | 理解、建议、提案——**你才是作者** |
| **你的角色** | 全部手动劳动 | 提供素材和规则，**信任 AI 的判断** | 判断什么值得留下，**决定哪些关系成立** |
| **产出是什么** | 你的笔记文件 | AI 维护的 Wiki 页面 | **你认可的知识**，存在你自己的 Markdown 里 |
| **失效模式** | 维护成本过高，最终放弃 | 幻觉污染、自信的错误、知识归属感丧失 | 需要你投入判断——但每次投入都在塑造你自己的知识体系 |
| **长期结果** | 收藏夹，越积越不想打开 | 一个你“拥有”但没读过的 Wiki | **一个你真正理解、信任、能回忆的外置认知系统** |

## 一次完整使用

```text
看到有价值的内容
      │
      ▼
采集：连同当时的想法一起保存        ← 保存的是「认知上下文」，不只是链接
      │
      ▼
Source留存：保存投递内容与原材料位置引用        ← 网页会消失，证据不会
      │
      ▼
AI 编译：阅读来源 → 形成知识草稿    ← 处理、去噪
      │
      ▼
AI 知识分析：分析知识提炼观点       ← 提炼要点、事实、主张、概念
AI 关系发现：指出与已有知识的联系    ← 支持、矛盾、替代、继承、实现、证据
      │
      ▼
══════ 人工闸门 ①  我认可哪些草稿与关系 ══════
      │
      ▼
AI 整合规划：决定如何融入已有体系    ← 优先复用已有结构，避免重复新建
      │
      ▼
变更提案：拆成可逐条决定的改动       ← 每条标明目标、改动前后、理由与来源
      │
      ▼
══════ 人工闸门 ②  我逐项批准哪些改动 ══════
      │
      ▼
正式知识（可追溯、可检索）
      │
      └──► 长期维护：只提案，不自动改动
```

## 核心能力

以下能力属于产品设计；实现进度见[开发状态](#开发状态)。

**📥 采集** — 几秒内把内容送进系统，同一个动作记下“为什么保存”。资料的价值一半来自内容，一半来自保存时你的判断。

**📸 来源留存** — 来源会改、会删、会失效。每条知识都能点回来源，看到当时的投递内容与原材料位置引用。论据沿「知识 → 来源记录 → 原材料」可完整回溯。

**🧠 知识编译** — AI 阅读来源，结合你保存时写下的想法和认识编译生成一份对原始材料去噪处理的草稿，最大程度的最重知识的来源同时去除无用噪音。

**🔎 草稿分析与关系发现** — AI在一旁给你提炼要点、主张、核对内容、提出疑问，辅助你你修改草稿；同时检索已有知识，指出新内容与旧知识的的联系、冲突，带类型、理由与出处，并给出与旧知识的整合线索，激发你的思考。

**⚖️ 人工确认闸门** — 并排呈现原始来源、你的批注、AI 的观点与关系建议。**这是「AI 认为」与「我认可」的分界点。** AI 不替用户拍板；经你审阅修改和认可的草稿才会进入知识库。

**📐 整合规划与变更提案** — 你确认后，AI 规划根据草稿、分析、你的整合意图及当前知识库，提出跨文件的新建、修改、重组、融合或废弃结果，统一生成候选的具体变更。你可以对照当前文件取舍内容、编辑候选或打回重新规划。AI会优先复用已有结构，改动透明、可解释、可撤销。

**📄 正式知识** — 批准后的内容以普通 Markdown 存入你的 Obsidian 库。独立使用的概念、原理和方法进入 `40_Knowledge`；围绕特定论文、实验或问题的结果、条件、证据和分析进入 `50_Research`。项目相关的特定知识进入`60_Projects`。**即使产品停止维护、AI 服务消失或索引损坏，正式知识仍完整存在。**

**🔍 检索与取回** — 支持从关键词、元数据、语义和关系等层次找回知识。即使只记得「我好像研究过这个」，也能迅速找回当时的知识、来源、想法与判断。

**🛠️ 知识维护** — 周期性检查知识库，提出整理、修复、更新与继续研究方向的建议。打开系统时自行查看，**维护建议由你主动查看，绝不自动推送、合并或删除**。

**🔬 科研工作区与项目工作区** — 以研究问题为中心，把假设、论文、实验与证据组织进 `50_Research`；以项目为中心，把项目相关的知识与材料组织进 `60_Projects`，**知识不再只是给未来的自己存档，而是围绕一个真实问题持续积累。**

**🔌 模型与 Agent 接入** — 每个 AI 任务都能分别选择 API 或 Agent 路径与模型，哪个环节交给谁由你决定；知识库也能开放给外部 AI 助手，让它们基于你的知识回答。**模型是租来的，知识是自己的——换一家 AI，知识库不用重建。**

## 三条不可妥协的约束

**🔐 数据主权** — 正式知识以普通 Markdown 存在你自己的 Obsidian 库里，论文与引用以 Zotero 为准。系统内部只保存索引、草稿、任务与提案这类派生数据，原则上都可重建。

**🛡️ 权限** — AI 只生成草稿、分析和提案。未经批准的候选不修改正式内容，批准后的变更由确定性执行器应用。正式文件的版本历史交给 Git；所有正式知识的修改都经你对比确认，并可完整回滚。

**🌱 长期演化** — 维护只建议、不推送；不做强制复习或提醒。随时记录，随用随取。

## 快速开始

### 环境依赖

- Windows 本地 NTFS。
- Node.js **24.19.0** 与 npm **11.17.0**；版本依据见 `.node-version` 与 `package.json`。
- 构建 Desktop 另需 Rust MSVC 工具链、Windows SDK 和 WebView2，见 [Desktop 说明](docs/desktop.md)。
- Obsidian 用于现有 Vault 的阅读与编辑；当前 Core 可独立运行。

### 安装与构建

```powershell
git clone https://github.com/EngramWeave/engramweave.git
cd engramweave
npm ci
npm run build
```

### 启动 Core

准备已有 Vault 和独立的应用数据目录，两者不能互相包含。把以下配置保存为 `D:/path/to/config.json`，替换为你的实际绝对路径：

```json
{
  "config_version": 1,
  "vault_path": "D:/path/to/vault",
  "data_dir": "D:/path/to/application-data",
  "host": "127.0.0.1",
  "port": 43127
}
```

```powershell
npm run core -- --config D:/path/to/config.json
```

启动后需显式扫描才会有检索结果。配置、认证、扫描、Capture 与恢复操作见 [Core 使用说明](docs/core.md)。

### 启动 Desktop

在另一终端中指定同一配置：

```powershell
$env:ENGRAMWEAVE_CONFIG = 'D:/path/to/config.json'
npm run desktop:dev
```

Desktop 可启动自身 Core，也可连接已运行的 Core。当前构建面向本机开发环境，尚未提供可分发安装包；操作说明见 [Desktop](docs/desktop.md)。
